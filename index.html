Optimistic & Pessimistic Locking (@Version)

PostgreSQL entity rows maintain an incremental version counter. When concurrent transactions attempt to book the same ticket, only the first transaction commits; subsequent transactions raise an OptimisticLockException and roll back cleanly. Together with pessimistic locking, this prevents concurrent overbooking, verified by a multithreaded test.

Redis Distributed Seat Lock with Auto-Expiration

Users reserve a seat for a 10-minute checkout window backed by Redis TTL keys (seat:{id}:lock). If the payment times out or the session abandons, the key naturally expires without blocking other customers.

Real-Time Seat Availability via STOMP WebSockets

State transitions trigger a broadcast event over an in-memory STOMP message broker. Connected browsers receive instantaneous seat map delta updates without high-overhead polling loops.

Dual-Token JWT Security & BCrypt Password Hashing

Short-lived access tokens (15m) paired with database-backed refresh token rotation ensure stateless REST verification while preserving instantaneous revocation capability upon security compromise. RBAC and per-resource ownership checks guard every endpoint, backed by a 6-test security regression suite.
